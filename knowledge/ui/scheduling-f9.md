# F9 排程（进度计算）

> 可信度：✅ 实测（25.12，2026-10-25）+ 📘 方法待教程补
> 一句话：**日期、浮时、关键路径都只认 F9 的结果**；插件只读，不自己算。

## 1. 操作

1. 打开项目 → **工具 → 进度（F9）**。
2. 对话框里确认“要计算进度的项目”数量 = 你要算的项目数。
3. 数据日期：默认“所有项目使用自己的数据日期”；需要统一时选“将选定的数据日期应用于所有打开的项目”。
4. 点 **进度**，等进度条结束。

> 对话框里“记录到文件”可留空；要排查时勾上，会写一份排程日志。

## 2. F9 会改什么（实测）

| 字段 | 行为 |
|---|---|
| `early_start/end`、`late_*` | 重新计算 |
| `total_float_hr_cnt` | 未开始活动的浮时从空变成具体值 |
| `remain_drtn_hr_cnt` | **未开始活动可能被重算**（曾见 999→120） |
| 活动/关系/分配数量 | 不变 |
| 目标日期（`target_*`） | 不变 |

所以：**不要自己推算日期**，也不要拿 F9 前的剩余工期当输入。

## 3. 常见结果与判断

| 现象 | 含义 | 处理 |
|---|---|---|
| 浮时为 0 | 关键活动（在最长路径上） | 正常；关键活动过多说明逻辑太紧或全是延时链 |
| 浮时为负 | 违反约束/项目完成日期 | 查约束、查 must-finish、查开口 |
| 有开口（无后继） | 活动没有后继关系 | 补里程碑或后续活动；否则浮时失真 |
| 日期比计划早/晚 | 逻辑或延时与目标窗口不一致 | 调 `lag` 或补约束，不要改 F9 结果 |

## 4. 里程碑与约束

- 0 工期 `Milestone` + `FS`：日期落在**后继工作日**（前一天完成，次日才算里程碑）。
- 要“某天必须发生”，用 `CS_MSO` + 日期（生成器支持）；这会压掉该活动的浮时，属正常。
- P6 的“完成里程碑（Finish Milestone）”与“开始里程碑（Start Milestone）”在排程上表现不同；本次实测中 `TT_FinMile` + `CS_MSO` 会落到前一日 17:00，改成 `TT_StartMile` 才落在当天。

## 5. 验证（读完必做）

```
p6 action=tasks project=<PROJECT> limit=200
```

看 `early_start / early_end / total_float`，与计划窗口逐项比对；插件导出的 Excel 也取这三列。
